## Critical

### C-01: Config path mismatch — agents and memory paths wrong

**File:** `config.yaml:26-27`
**Severity:** Critical

```yaml
agents_path: "./agents/prompts"    # SHOULD BE: "./.agents/prompts"
memory_path: "./memory"            # SHOULD BE: "./.memory"
```

Both paths are missing the leading dot — actual directories are `.agents/prompts/` and `.memory/`. Any code reading these paths at runtime will fail to find the target files.

**Fix:** Add the leading dot to match actual filesystem layout:
```yaml
agents_path: "./.agents/prompts"
memory_path: "./.memory"
```

---

### C-02: Orchestrator agent count inconsistency (4 vs 5 agents)

**File:** `.agents/prompts/orchestrator.md:76-77,81,85`
**Severity:** Critical

Phase 2 references "the 4 agents run in parallel" and "Confirm all 4 agents received proper assignments," but Phase 3 header says "only when all 5 agent files are complete." The `AGENTS.md:74-79` maps 5 agents (indic, western, civilizations, contemporary, science).

The system has 5 agents. The orchestrator prompt was either written when there were 4 or was not updated when `science_technology` was added.

**Fix:** Change all "4 agents" references in orchestrator.md Phase 2 to "5 agents":
- Line 76: "the 5 agents run in parallel"
- Line 78: "Confirm all 5 agents received proper assignments"
- Line 81: "If any agent fails or times out..."

Same issue in `agent_atomic_notes.md` and `prompt_updater.md`.

### W-02: Duplicate "Key rules" sections in agent prompts

**Files:** Multiple agents
**Severity:** Warning

Three agent prompts have duplicate/overlapping instruction sections:

- **`agent_a_indic.md:53-80`** — duplicate "Key rules" block for blockquote formatting (same structure as lines 40-51 but with Tibetan examples). Lines 58-80 are a verbatim repeat with different script examples.
- **`agent_b_western.md:66-80`** — duplicate "Key rules" for script handling (Hebrew/German examples) repeating the same structure as lines 52-64.
- **`agent_c_civilizations.md:86-115`** — duplicate "Key rules" reinforcing same formatting instructions already covered in lines 69-84.

These duplicates add ~30 redundant lines per agent file, consume token budget, and risk contradictory instructions if one copy diverges during editing.

**Fix:** Merge into single "Key rules" section per agent. Retain unique examples, remove verbatim repeats.

---

### W-03: Inconsistent timestamp format in domain_memory.json

**File:** `.memory/domain_memory.json:3,16`
**Severity:** Warning

`last_updated: "2026-05-19T07:20:00Z"` but `timestamp: "2026-05-18T23:48:00Z"` — both valid ISO 8601 but inconsistent format. Standardize on a single format (both include T and Z already, so this is about the time value discrepancy itself — the `last_updated` is 8 hours after the run timestamp which is expected, but the consistency of trailing `Z` vs offset format matters).
